### 4. 优化战斗状态判定逻辑

**文件**: `main.js:263-298`

更新 `shouldEnterBattle()` 函数：

```javascript
async shouldEnterBattle() {
    // 第一步：检查工具栏是否禁用
    const tooldisabledResult = await recognizeImage(TooldisabledRo);
    if (!tooldisabledResult.success) return false;

    // 第二步：检查派蒙菜单是否存在
    const paimonResult = await recognizeImage(PaimonRo);
    if (!paimonResult.success) return false;

    // 第三步：检查是否处于特殊移动状态（新增）
    const specialState = await checkSpecialMovementStates();
    if (specialState.isSpecialState) {
        log.debug(`检测到特殊移动状态【${specialState.stateDescription}】，跳过战斗检测`);
        return false;
    }

    // 所有条件满足，进入战斗
    log.info("满足战斗状态条件，准备启动自动战斗");
    return true;
}
```

**改进点**：
- ✅ 使用统一的状态检测函数
- ✅ 更清晰的三步检测流程
- ✅ 详细的中文日志输出
- ✅ 更好的代码可维护性

## 🔍 技术细节

### 状态检测优先级

1. **攀爬状态** (最高优先级)
   - 图标：Climb.png
   - 位置：(1596, 1027)
   - 检测时机：实时检测

2. **游泳状态**
   - 图标：Swim.png
   - 位置：(1811, 1027)
   - 检测时机：攀爬检测失败后

3. **交互状态** (最低优先级)
   - 图标：Space.png
   - 位置：(1683, 1027) 和 (1579, 1027)
   - 检测时机：攀爬和游泳检测失败后

### 性能优化

- **检测超时**: 200ms（CONFIG.QUICK_CHECK_TIMEOUT）
- **识别延迟**: 50ms（CONFIG.RECOGNITION_DELAY）
- **缓存机制**: 识别对象在脚本启动时创建，避免重复创建

### 错误处理

- 配置读取失败时使用默认值
- 识别异常时记录错误日志并继续运行
- 提供详细的调试日志
