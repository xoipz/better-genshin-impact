```csharp
public static string NormalizePath(string root, string path)
{
    // convert to full path relative to root
    path = path.Replace('\\', '/');
    var fullPath = Path.GetFullPath(Path.Combine(root, path));

    // if root is locked, make sure didn't attempt to exit it
    if (!fullPath.StartsWith(root))
    {
        throw new ArgumentException($"Path '{path}' is not allowed, because its outside the caged root folder!");
    }

    // return full path
    return fullPath;
}
```

## 4. JS文件导入方法

### 4.1 eval() + file.readTextSync() 方式

### 4.2 CommonJS require() 方式（存在兼容性问题）

⚠️ **重要提醒**: 基于AutoCommission项目的实战研究发现，CommonJS方式存在稳定性问题，建议谨慎使用。

**理论支持**:
```javascript
// 假设有 lib/utils.js 文件
const utils = require('./lib/utils');
const ocr = require('./lib/ocr');

// 使用导入的模块
utils.someFunction();
ocr.recognizeText();
```

**实际问题**:
- 经常出现"require is not defined"错误
- 需要精确的manifest.json配置
- 在不同BGI版本中表现不一致

**重大技术发现**: 经过深入研究发现，BGI环境下的模块化开发存在变量声明类型的根本性限制。详情请参考: [BGI JavaScript脚本模块导入方式选择指南](./07-JS脚本模块导入方式选择指南.md)

### 4.3 推荐的var+eval方式

基于AutoCommission项目的技术突破，推荐使用以下经过验证的方式：

**模块声明** (必须使用var):
```javascript
// lib/utils.js
var Utils = {
  sleep: function(ms) {
    return new Promise(resolve => setTimeout(resolve, ms));
  },
  
  randomDelay: function(min, max) {
    const delay = Math.random() * (max - min) + min;
    return this.sleep(delay);
  }
};
```

**模块加载** (顶层直接eval):
```javascript
// main.js
eval(file.readTextSync("lib/utils.js"));
eval(file.readTextSync("lib/constants.js"));

// 现在可以直接使用
log.info("版本: " + Constants.VERSION);
await Utils.randomDelay(1000, 2000);
```

**关键技术要点**:
1. **使用var声明**: `const`声明无法跨eval作用域传递
2. **顶层执行**: 必须在main.js顶层直接调用eval
3. **避免包装**: 任何函数或try-catch包装都会导致作用域隔离

### 5.2 模块化编写规范

#### 5.2.1 库文件编写示例 (lib/utils.js)
```javascript
// 工具函数模块 - 必须使用var声明
var Utils = {
    sleep: function(ms) {
        return new Promise(resolve => setTimeout(resolve, ms));
    },
    
    randomDelay: function(min, max) {
        const delay = Math.random() * (max - min) + min;
        return this.sleep(delay);
    },
    
    retry: async function(fn, maxAttempts = 3) {
        for (let i = 0; i < maxAttempts; i++) {
            try {
                return await fn();
            } catch (error) {
                if (i === maxAttempts - 1) throw error;
                await this.sleep(1000);
            }
        }
    }
};

// ❌ 移除CommonJS导出（在BGI环境中不需要）
// if (typeof module !== 'undefined' && module.exports) {
//     module.exports = Utils;
// }
```

#### 5.2.2 主文件使用示例 (main.js)
```javascript
log.info("开始加载模块...");

// 顶层直接eval - 这是唯一正确的方式
eval(file.readTextSync("lib/constants.js"));
eval(file.readTextSync("lib/utils.js"));
eval(file.readTextSync("lib/ui.js"));

log.info("所有模块加载完成");

// 模块加载验证
function checkModulesLoaded() {
    const requiredModules = ['Constants', 'Utils', 'UI'];
    const missingModules = [];
    
    for (const moduleName of requiredModules) {
        try {
            const moduleType = eval("typeof " + moduleName);
            if (moduleType === 'undefined') {
                missingModules.push(moduleName);
            }
        } catch (error) {
            missingModules.push(moduleName);
        }
    }
    
    return missingModules.length === 0;
}

// 主逻辑
const Main = async () => {
    try {
        if (!checkModulesLoaded()) {
            log.error("模块加载失败，脚本终止");
            return;
        }
        
        log.info("版本: " + Constants.VERSION);
        
        // 使用导入的模块
        await Utils.randomDelay(1000, 2000);
        const result = await UI.someUIMethod();
        
        log.info("脚本执行完成");
    } catch (error) {
        log.error("执行出错: " + error.message);
    }
};

// 使用IIFE包装返回Promise
(async () => {
    return await Main();
})();
```

## 9. 最佳实践建议

### 9.1 模块设计原则
1. **单一职责**: 每个模块只负责一个特定功能
2. **松耦合**: 模块间依赖关系要清晰简单
3. **高内聚**: 相关功能放在同一模块内
4. **可重用**: 编写通用的工具函数和组件

### 9.2 BGI环境特殊要求

⚠️ **重要**: 基于AutoCommission项目的技术发现，BGI环境下的模块化开发必须遵循以下要求：

#### 9.2.1 变量声明要求
```javascript
// ✅ 正确 - 使用var声明
var ModuleName = {
    method: function() {}
};

// ❌ 错误 - const声明无法跨eval上下文
const ModuleName = {
    method: function() {}
};
```

#### 9.2.2 模块加载要求
```javascript
// ✅ 正确 - 顶层直接eval 
eval(file.readTextSync("lib/module.js"));

// ❌ 错误 - 任何包装都会导致作用域隔离
try {
    eval(file.readTextSync("lib/module.js"));
} catch (error) {
    // 处理错误
}
```

#### 9.2.3 脚本返回要求
```javascript
// ✅ 正确 - 使用IIFE包装return
(async () => {
    return await Main();
})();

// ❌ 错误 - 直接return会导致语法错误
return Main();
```

### 9.3 文件组织建议
1. **lib/**: 放置核心库文件和工具函数（使用var声明）
2. **modules/**: 放置功能模块（使用var声明）
3. **config/**: 放置配置文件
4. **data/**: 放置数据文件和模板
5. **tests/**: 放置测试文件（如果需要）

### 9.4 迁移指南

如果您现有的脚本使用了const声明或CommonJS模式，需要进行以下迁移：

#### 从const迁移到var
```javascript
// 旧代码 (不工作)
const Utils = { method: function() {} };

// 新代码 (工作)
var Utils = { method: function() {} };
```

#### 从CommonJS迁移到eval
```javascript
// 旧代码 (可能不工作)
const utils = require('./lib/utils');

// 新代码 (稳定工作)
eval(file.readTextSync("lib/utils.js")); // 其中定义var Utils = {}
```
