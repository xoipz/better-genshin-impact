**✅ 确认可用的功能**：

**📝 实际使用建议**：
1. 使用 `new SoloTask("任务名")` 创建任务
2. 通过 `dispatcher.runTask(task)` 执行任务
3. 任务控制完全通过dispatcher进行，SoloTask实例仅作为任务标识

## 取消令牌机制

取消令牌（CancellationToken）是BGI任务系统中用于控制任务生命周期的重要机制，允许脚本优雅地取消正在运行的任务。

**代码位置**: `Dispatcher.cs:297-307` (GetLinkedCancellationTokenSource和GetLinkedCancellationToken方法)

### 取消令牌的作用

取消令牌提供了以下能力：
- ✅ **优雅取消**: 允许任务在安全的时机停止执行
- ✅ **资源清理**: 确保任务取消时正确释放资源
- ✅ **超时控制**: 实现任务执行的超时机制
- ✅ **用户中断**: 响应用户的停止请求

### dispatcher.getLinkedCancellationTokenSource()

创建一个链接到全局取消令牌的新令牌源。

```javascript
// 创建链接的取消令牌源
const linkedCts = dispatcher.getLinkedCancellationTokenSource();

// 获取令牌
const token = linkedCts.Token;

// 在任务中使用
const task = new SoloTask("AutoFishing");
await dispatcher.runTask(task, token);

// 取消任务
linkedCts.Cancel();
```

**特性**:
- 链接到全局取消令牌（当脚本停止时自动取消）
- 可以独立取消，不影响其他任务
- 支持多个任务共享同一个令牌源

**代码位置**: `Dispatcher.cs:297-301`

### dispatcher.getLinkedCancellationToken()

直接获取一个链接到全局令牌的取消令牌（快捷方法）。

```javascript
// 快捷方式：直接获取令牌
const token = dispatcher.getLinkedCancellationToken();

// 在任务中使用
const task = new SoloTask("AutoWood");
await dispatcher.runTask(task, token);
```

**注意**: 这个方法返回的是令牌本身，无法主动取消，只能响应全局取消。

**代码位置**: `Dispatcher.cs:304-307`

### 使用场景

#### 1. 任务超时控制

```javascript
async function runTaskWithTimeout(taskName, timeoutMs) {
    try {
        // 创建取消令牌源
        const cts = dispatcher.getLinkedCancellationTokenSource();

        // 设置超时取消
        setTimeout(() => {
            cts.Cancel();
            log.warn(`任务 ${taskName} 执行超时，已取消`);
        }, timeoutMs);

        // 执行任务
        const task = new SoloTask(taskName);
        await dispatcher.runTask(task, cts.Token);

        log.info(`任务 ${taskName} 在超时前完成`);
    } catch (error) {
        if (error.message.includes("cancel")) {
            log.warn(`任务 ${taskName} 被取消`);
        } else {
            log.error(`任务 ${taskName} 执行失败: ${error.message}`);
        }
    }
}

// 使用示例：30秒超时
await runTaskWithTimeout("AutoFishing", 30000);
```

async function runTaskWithCondition(taskName, checkCondition) {

    // 定期检查条件，满足时取消任务

async function runMultipleTasksWithSharedCancellation() {

}

## 注意事项

### ⚠️ 重要提醒 - 基于实际测试结果

1. **SoloTask构造限制**：只能使用 `new SoloTask("任务名")` 单字符串参数构造
2. **属性访问限制**：SoloTask只有Name和Config两个属性，Config通常为null
3. **方法调用限制**：SoloTask实例不包含Start、Stop等控制方法
4. **任务配置机制**：Config属性无效，任务配置需要通过其他方式设置（机制尚不明确）
5. **取消令牌管理**：及时清理未使用的CancellationTokenSource
6. **错误处理**：所有异步任务都应该有适当的错误处理
7. **资源管理**：长时间运行的任务应该定期检查取消令牌状态

async function multiDomainRoutine() {

    ];

    for (const domain of domains) {
        try {
            log.info(`开始刷取: ${domain.name}`);

            // 切换队伍
            await genshin.SwitchParty(domain.party);

            // 配置并执行秘境
            const domainParam = new AutoDomainParam(domain.rounds);
            domainParam.DomainName = domain.name;
            domainParam.PartyName = domain.party;

            await dispatcher.RunAutoDomainTask(domainParam);

            log.info(`${domain.name} 完成`);
            await sleep(2000);

        } catch (error) {
            log.error(`${domain.name} 失败:`, error.message);
            continue; // 继续下一个秘境
        }
    }

    notification.send("所有秘境刷取完成！");
}
